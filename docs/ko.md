# 홍콩 하루 일정 만들기 — 처음 시작하는 사람용

2026-09-12 · 여행 템플릿 v0.1 · 자체 테스트용 초안, 실제 실행 미확인

준비된 팀을 실행하고 → 내 취향과 지시를 바꾸고 → 다시 사용합니다. 프로그래밍은 하지 않습니다. 노트북·인터넷·이메일 확인 수단을 준비하세요. [영문 가이드](index.html)도 같은 흐름입니다.

<h2 id="step-1">1. 오늘 사용할 팀</h2>

| 하는 일 | 화면 이름 | 결과 |
| --- | --- | --- |
| 활동 추천 | Activity Selector | 관심사에 맞는 활동과 추천 이유 |
| 일정 구성 | Day Planner | 방문 순서와 식사·휴식 |
| 조건 확인·수정 | Plan Reviewer | 요청을 검토한 최종 일정 초안 |

정해진 순서로 AI가 답변을 전달하는 작은 팀입니다. 검색·예약은 하지 않습니다. 제공된 장소 자료로 초안을 만들며 운영시간, 가격, 이동시간, 접근성은 방문 전에 따로 확인해야 합니다.

**템플릿**은 역할과 연결이 미리 준비된 예제 파일입니다. 이번 실습은 정확한 여행 상품보다 “지시를 바꾸면 팀의 결과가 어떻게 달라지는가”에 집중합니다.

<h2 id="step-2">2. 왜 사이트 두 곳에 가입하나요?</h2>

| 사이트 | 하는 일 |
| --- | --- |
| Sim | AI 팀을 눈으로 보고 지시를 수정하고 실행하는 화면 |
| OpenRouter | AI 답변을 이용할 수 있게 연결해 주는 서비스 |

두 사이트를 연결하려면 OpenRouter가 발급하는 개인 연결 코드가 필요합니다. 이것을 **API 키**라고 합니다. Sim이 내 계정으로 AI에 요청할 수 있도록 허용하는 코드이며 로그인 비밀번호와는 다릅니다.

가이드는 한 탭에 열어 두고 사이트는 다른 탭에 여세요. 예제는 무료 AI 선택지를 사용하지만 이용 제한이 있을 수 있습니다. 결제나 업그레이드가 필요하다고 나오면 구매하지 말고 진행자에게 알려주세요.

<h2 id="step-3">3. OpenRouter에서 개인 연결 코드 만들기</h2>

1. [OpenRouter](https://openrouter.ai/)를 열어 가입합니다. 계정이 있다면 로그인합니다.
2. 이메일 인증을 요청받으면 받은 메일에서 인증한 뒤 사이트로 돌아옵니다. 메일이 없으면 스팸함도 확인합니다.
3. 로그인 후 [API Keys 화면](https://openrouter.ai/settings/keys)을 엽니다.
4. 새 키를 만드는 항목을 선택하고 이름을 `polyu-pilot`으로 입력합니다.
5. 생성된 긴 코드 옆의 복사 버튼을 누릅니다. 이름 `polyu-pilot`이 아니라 **긴 코드**를 복사해야 합니다.
6. 다음 단계까지 이 페이지를 열어 두세요. 나중에 보관할 때는 비밀번호 관리자처럼 개인적으로 보관할 수 있는 곳을 사용합니다.

완료 확인: 개인 키를 복사했습니다. 이 코드는 채팅, 교수님께 보내는 메시지, 화면 캡처에 넣지 않습니다.

<h2 id="step-4">4. Sim에 가입하고 코드 연결하기</h2>

Sim은 내 작업 공간을 **workspace**라고 부릅니다. 만든 팀은 이 공간에 저장됩니다.

1. 새 탭에서 [Sim](https://www.sim.ai/)을 열어 가입하거나 로그인합니다.
2. 요청되는 이메일 인증을 완료하고 내 작업 공간으로 들어갑니다.
3. 작업 공간의 **Settings(설정)**를 열고 **Secrets(비밀값 보관)**를 선택합니다.
4. Workspace 구역의 빈 줄에 다음 두 값을 입력합니다.

| 입력란 | 넣을 내용 |
| --- | --- |
| Key 또는 Name | `OPENROUTER_API_KEY`를 그대로 복사 |
| Value | OpenRouter에서 복사한 긴 개인 코드 |

5. **Save(저장)**를 누릅니다. 저장 후 코드가 가려져 보일 수 있습니다.
6. Sim의 작업 화면으로 돌아옵니다.

예제는 위 이름으로 저장된 코드를 찾아 씁니다. 예제 안의 `{{OPENROUTER_API_KEY}}`는 '저장된 키를 사용하라'는 표시이지 실제 키가 아닙니다. [공식 설정 안내](https://docs.sim.ai/platform/credentials)

완료 확인: 저장한 키 이름이 보입니다. 설정 위치를 못 찾겠으면 해당 단계에서 도움을 요청하세요. 이름이 비슷한 'Sim API keys'는 다른 기능입니다.

<h2 id="step-5">5. 준비된 팀 파일 불러오기</h2>

Sim은 여러 작업을 순서대로 묶어둔 것을 **workflow(워크플로)**라고 부릅니다. 파일에 역할과 연결이 이미 준비되어 있습니다.

1. [실습 시작 파일](assets/templates/hong-kong-day-trip-team-starter-v0.1.json)을 내려받습니다. 따로 첨부받았다면 그 파일을 다운로드합니다. **JSON**은 파일 형식의 이름이며 내용을 읽거나 고칠 필요는 없습니다.
2. 링크를 눌렀는데 글자만 보이면 다운로드 기능으로 원래의 `.json` 파일을 저장합니다. 내용을 Sim 상자에 붙여넣지 않습니다.
3. Sim 왼쪽의 **Workflows** 제목을 찾습니다.
4. 그 제목 옆 **···** 메뉴를 열어 **Import(파일 불러오기)**를 선택합니다.
5. 내려받은 `hong-kong-day-trip-team-starter-v0.1.json`을 선택합니다.
6. 목록에 추가된 **Hong Kong Day Trip Team - Starter v0.1**를 엽니다.

완료 확인: Start, Activity Selector, Day Planner, Plan Reviewer라는 상자 네 개가 연결되어 보입니다. 이런 상자를 **block(블록)**이라고 부릅니다.

Start는 여행 요청과 장소 자료를 넣는 자리이고 나머지 세 개는 앞서 소개한 AI 담당자입니다. **모델**은 답변을 만드는 AI를 뜻합니다. 사용할 모델은 예제에 선택되어 있어 지금 고를 필요가 없습니다.

<h2 id="step-6">6. 여행 요청을 확인하고 실행하기</h2>

1. **Start**를 클릭하고 오른쪽 **Editor**를 엽니다.
2. **trip → Value**는 이번 여행 요청입니다. 기본값은 항구 풍경·사진·공원에 관심이 있고 여유롭게 하루를 보내고 싶다는 내용입니다.
3. **places → Value**는 제공된 장소 자료입니다. 처음에는 두 항목 모두 그대로 둡니다.
4. 오른쪽 위 **Run**을 누릅니다. 저장된 값을 사용하므로 새 입력창이 뜨기를 기다리지 않습니다.
5. 끝날 때까지 기다립니다. Run을 반복해서 누르지 않습니다.
6. 아래 **Logs**에서 최신 실행을 선택하고 **Plan Reviewer → content**를 읽습니다. content는 AI가 작성한 답변입니다.

완료 확인: 제공된 활동으로 만든 일정 초안이 보입니다. 자료에 없는 시간·가격 등이 사실처럼 쓰였다면 표시해 둡니다. AI의 검토도 정확성을 보장하지 않습니다.

<h2 id="step-7">7. 역할과 지시문 이해하기</h2>

같은 실행의 Activity Selector → Day Planner → Plan Reviewer 답변을 읽습니다. 한 장소가 추천에서 최종 일정으로 어떻게 이어지는지 찾아보세요.

**Day Planner → Editor → Messages**를 엽니다.

| 화면 이름 | 뜻 |
| --- | --- |
| System | 이 AI의 역할·행동 원칙·출력 규칙 |
| User | 이번 작업의 요청과 자료 |

둘 다 AI에게 전달하는 문장이며 **프롬프트**라고 부릅니다. 코드처럼 작성할 필요는 없습니다.

User의 `<activityselector.content>`는 앞 AI의 답변이 들어오는 자리입니다. 실행할 때 Sim이 채웁니다.

| 표시 | 전달되는 내용 |
| --- | --- |
| `<start.trip>` | 여행 요청 |
| `<start.places>` | 제공된 장소 자료 |
| `<activityselector.content>` | 추천 담당의 답변 |
| `<dayplanner.content>` | 일정 구성 담당의 답변 |

기본 실습에서는 이 표시나 블록 이름을 바꾸지 않습니다. 화살표는 실행 순서를, 메시지의 참조는 사용할 결과를 지정합니다.

<h2 id="step-8">8. 내 취향과 지시 바꾸기</h2>

### A. 이번 여행의 관심사 바꾸기

**Start → trip → Value**를 아래 예시로 교체하거나 자신의 관심사로 작성합니다. **places는 그대로 둡니다.**

```text
Plan a relaxed one-day visit to Hong Kong using only the supplied activity cards.
Interests: art and harbour views.
Pace: relaxed.
Return a draft, not a confirmed travel schedule.
```

“예술과 항구 풍경에 관심이 있다”는 요청입니다. 자신이 좋아하는 활동으로 바꿔보세요.

### B. 검토 담당에게 조건 추가하기

**Plan Reviewer → Editor → Messages → System**의 기존 글 끝에 다음 문장을 **추가**합니다. User는 변경하지 않습니다.

```text
Keep at most two sightseeing activities and include at least one rest break. Remove extra sightseeing activities from the draft if needed. Explain briefly what you changed, or say that the draft already met this rule.
```

관광 활동을 최대 두 개로 줄이고 휴식을 하나 이상 넣으며, 수정 사항을 짧게 설명하라는 뜻입니다. 이는 확인된 여행 사실이 아니라 내가 새로 정한 조건입니다.

완료 확인: 여행 요청을 바꾸는 칸과 담당 AI의 행동 규칙을 바꾸는 칸이 다르다는 것을 설명할 수 있습니다.

<h2 id="step-9">9. 다시 실행하고 확인하기</h2>

1. 입력란 밖을 클릭하고 저장 버튼이 보이면 저장합니다.
2. **Run**으로 다시 실행합니다.
3. **Logs**에서 새 실행 시각을 확인하고 **Plan Reviewer → content**를 읽습니다.

확인할 것은 네 가지입니다.

- 내 관심사에 맞는 활동인가?
- 관광 활동은 두 개 이하이며 휴식이 포함됐는가?
- 제공된 자료 밖의 장소나 근거 없는 시간·가격을 추가하지 않았는가?
- 바꾼 점 또는 이미 조건을 충족했다는 설명이 있는가?

처음부터 조건에 맞았다면 큰 변화가 없어도 괜찮습니다. 전체 재실행은 앞 AI의 답변도 달라질 수 있어 엄밀한 비교 실험은 아닙니다. 규칙 위반이 남으면 표시하고 도움을 요청하세요.

먼저 끝났다면 관심사나 조건 하나를 더 바꿔보세요. 기본 완료는 내 선택을 반영해 다시 실행하는 것입니다. 다른 여행을 만들 때는 장소 자료도 교체하고 정확성을 따로 확인해야 합니다.

<h2 id="step-10">10. 다음에도 사용할 수 있게 남기기</h2>

1. 왼쪽 목록에서 다른 팀을 열었다가 내 팀으로 돌아와 수정한 문장이 남아 있는지 봅니다.
2. 화면에 저장 동작이 있으면 완료하고, 로그아웃했다가 다시 로그인해 같은 팀을 실행합니다.
3. 파일로도 남기려면 왼쪽 목록의 팀 이름을 우클릭하고 **Export(파일로 내보내기)**를 선택합니다. [공식 가져오기·내보내기 안내](https://docs.sim.ai/quick-reference)

다음에는 저장된 팀을 열어 Start의 trip 내용을 바꾸고 Run을 누르면 됩니다. 내보낸 파일은 팀 설정을 담습니다. 무료 이용권이나 실제 개인 키가 담긴 것은 아닙니다. 다른 곳에 키를 직접 입력했다면 파일을 공유하기 전에 포함 여부를 확인하세요.

<h2 id="help">막혔을 때</h2>

| 상황 | 다음 행동 |
| --- | --- |
| 인증 메일이 안 옴 | 주소와 스팸함 확인 |
| 메뉴나 결과 위치를 못 찾음 | 몇 번 단계인지 알리고 도움 요청 |
| 키가 없거나 인증 오류가 남 | 현재 팀이 있는 작업 공간에 `OPENROUTER_API_KEY`로 저장했는지 확인 |
| `429 Provider returned error` | 재실행 반복을 멈추고 진행자에게 오류 전달 |
| 결제 안내가 나옴 | 구매하지 말고 멈춘 단계 기록 |
| AI가 자료가 없다고 함 | Start의 trip과 places Value가 비어 있지 않은지 확인 |
| 예전 답변처럼 보임 | Logs에서 최신 실행 시각 확인 |
| 결과가 크게 달라지지 않음 | 최신 실행인지 확인하고, 관심사와 추가 조건 충족 여부를 점검 |

도움을 받을 때 개인 키가 화면에 노출되지 않게 합니다.
