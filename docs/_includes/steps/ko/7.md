## A. 직접 구성한 시스템 실행하기

1. **Run**을 한 번 누르세요. Start의 저장된 값을 사용하며 별도의 입력창은 열리지 않습니다.
2. 완료될 때까지 기다리고 Run을 반복해서 누르지 마세요.
3. **Logs**에서 최신 실행을 선택하고 **Review Analyst → content**, **Operations Advisor → content**를 읽으세요.
4. **Guest Reply Writer → content**에서 고객 답변 초안을 확인하세요.

분석 담당은 어떤 의견을 정리했나요? 운영 담당은 그중 어떤 불편 사항을 활용했나요? 소통 담당의 답변에 앞 담당자들의 결과가 어떻게 반영됐는지 살펴보세요.

## B. 고객 답변에 조건 추가하기

**미션: 고객의 두 불편 사항을 모두 언급하는 짧은 답변을 만들어보세요.**

어느 역할에 요청할까요? 이번에는 고객 소통 담당에게 요청합니다. **Guest Reply Writer → Editor → Messages → User** 끝에 아래 문장을 추가하세요. 원문·참조·System은 그대로 둡니다.

```text
For this reply, address both the check-in wait and the missing breakfast-hours information. Keep it under 90 words.
```

다시 Run을 누르고 최신 답변을 확인하세요.

- 체크인 대기와 조식 시간 안내 누락을 모두 다뤘나요?
- 분석 담당이 정리한 고객 의견이 답변에도 반영됐나요?
- 운영 담당의 제안 중 답변 작성에 참고한 부분을 찾을 수 있나요? 제안 전체를 그대로 옮길 필요는 없습니다.
- 짧은 답변에서도 감사와 불편에 대한 공감이 유지되나요?

처음부터 조건을 충족했다면 변화가 작을 수 있습니다. **역할과 연결이 의도대로 작동하고 요청 조건이 반영됐는지** 확인하세요. 전체 재실행에서는 앞 담당자의 결과도 달라질 수 있습니다.

## C. 선택: 답변 형식 바꾸기

시간이 남으면 User는 그대로 두고 소통 담당의 **System 끝**에 다음 규칙을 추가하세요.

```text
Use two short paragraphs: first thank the guest and acknowledge the concerns; then close politely without promising actions. Keep all existing factual and safety constraints.
```

한 번 더 실행해 형식을 확인하세요. User는 이번 답변의 요청, System은 담당자가 따를 기본 규칙을 전달합니다.
