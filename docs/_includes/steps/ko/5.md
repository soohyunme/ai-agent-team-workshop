이번 실행에서는 **제공된 관광·식사 자료**를 바탕으로 일정 초안을 작성합니다. 실시간 검색이나 예약은 하지 않습니다. 식사 후보는 **실습용 가상 예시**이며 실제 식당이나 메뉴 정보가 아닙니다.

## 첫 일정 생성하기

1. **Start**를 클릭하고 오른쪽 **Editor(편집)**를 여세요.
2. **trip → Value**에서 관광 취향, 음식 취향, 여행 속도를 확인하세요. 기본 요청은 항구 풍경·사진·공원과 현지 음식입니다.
3. **places → Value**에서 관광 자료와 가상 식사 자료를 확인하세요. 각 항목에는 식별 번호와 지역이 있습니다. 첫 실행에서는 값을 수정하지 마세요.
4. 오른쪽 위 **Run(실행)**을 누르세요. Start에 저장된 값을 사용하므로 별도의 입력창은 열리지 않습니다.
5. 실행이 끝날 때까지 기다리세요. 실행 중에는 Run을 반복해서 누르지 마세요.
6. 아래 **Logs(실행 기록)**에서 최신 실행을 선택하고 **Trip Planner → content**를 여세요. content는 AI가 작성한 답변입니다.

관광·식사·휴식이 하나의 초안으로 구성됐는지 살펴보세요. 가상 식사 예시를 실제 식당처럼 설명하거나 근거 없는 이동시간을 제시했다면 표시해 두세요.

## 역할별로 전달한 정보 확인하기

같은 실행 기록을 순서대로 읽으세요.

| 담당자 | 확인할 내용 |
| --- | --- |
| Sightseeing Planner | 어떤 관광지와 지역을 선택했나요? |
| Food Planner | 선택된 관광지의 지역과 음식 취향을 기준으로 식사 후보를 골랐나요? |
| Trip Planner | 두 담당자의 추천을 어떻게 묶어 일정을 만들었나요? |

예를 들어 관광 담당이 침사추이의 관광지를 선택했다면, 식사 담당이 침사추이로 표시된 가상 식사 후보를 선택했는지 확인하세요. 해당 지역·취향에 맞는 후보가 없으면 임의로 만들어내지 않고 자료가 부족하다고 설명해야 합니다.

이어서 **Food Planner → Editor → Messages(메시지)**를 여세요.

| 메시지 종류 | 용도 |
| --- | --- |
| System | 에이전트의 역할, 행동 원칙, 출력 규칙 |
| User | 이번 실행에서 처리할 요청과 자료 |

AI에게 전달하는 지시문을 **프롬프트(prompt)**라고 합니다. 일반 문장으로 작성할 수 있습니다.

Food Planner의 User 메시지에 있는 `<sightseeingplanner.content>`는 관광 담당의 답변을 가져오는 **참조**입니다. 식사 담당은 이 결과와 원래 자료를 함께 읽습니다.

| 참조 표시 | 전달되는 내용 |
| --- | --- |
| `<start.trip>` | 관광·음식 취향과 여행 조건 |
| `<start.places>` | 지역이 표시된 관광·가상 식사 자료 |
| `<sightseeingplanner.content>` | 선택된 관광지와 지역 |
| `<foodplanner.content>` | 식사 후보와 관광지 지역의 연결 이유 |

마지막 Trip Planner는 두 담당자의 답변을 모두 받습니다. 화살표는 실행 순서를, 메시지의 참조는 전달할 내용을 지정합니다. 기본 실습에서는 블록 이름과 참조 표시를 변경하지 마세요.
