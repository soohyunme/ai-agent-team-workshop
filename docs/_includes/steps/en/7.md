## A. Run the system you built

1. Select **Run** once. It uses saved Start values; no separate input window opens.
2. Wait for completion without repeatedly selecting Run.
3. In **Logs**, select the latest run and read **Review Analyst → content** and **Operations Advisor → content**.
4. Open **Guest Reply Writer → content** to read the reply draft.

Is the analysis grounded in the review? Does each proposal address a concern? Does the reply avoid turning proposals into completed actions or promises?

## B. Add conditions for the guest reply

**Mission: address both concerns in a short reply without claiming unverified improvements or promising compensation.**

Which role should receive this request? Here, ask the guest communicator. Append the following to **Guest Reply Writer → Editor → Messages → User**, leaving the review, references and System unchanged.

```text
For this reply, address both the check-in wait and the missing breakfast-hours information. Keep it under 90 words. Do not claim that improvements are completed or promise compensation.
```

Run again and check the latest reply.

- Does it address both the check-in wait and missing breakfast-hours information?
- Does it avoid invented causes, hours and hotel policies?
- Does it avoid claims of completed improvements or promises of compensation or follow-up action?
- Does the short reply still express thanks and acknowledge the guest's concerns?

Safety rules already exist in the baseline. A reply that met the conditions may change little; do not expect an error on every run. Check **evidence and requirements**. Rerunning the system can also change the earlier outputs.

## C. Optional: change the reply format

If time allows, leave User unchanged and append this rule to the communicator's **System**.

```text
Use two short paragraphs: first thank the guest and acknowledge the concerns; then close politely without promising actions. Keep all existing factual and safety constraints.
```

Run once more to check the format. User supplies the request for this reply; System sets the role's general rules.

## Before real-world use

A human must check the draft against the original review, actual hotel policies and approved actions. Do not submit personal details, booking numbers or other sensitive guest data to external services. This exercise generates drafts only; it does not send or publish replies.
