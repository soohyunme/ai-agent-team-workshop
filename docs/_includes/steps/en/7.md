## A. Run the system you built

1. Select **Run** once. It uses saved Start values; no separate input window opens.
2. Observe the analyst and operations advisor running independently, followed by the communicator after both finish. Wait for completion without repeatedly selecting Run.
3. In **Logs**, select the latest run and read **Review Analyst → content** and **Operations Advisor → content**.
4. Open **Guest Reply Writer → content** to read the reply draft.

Which feedback did the analyst identify? What checks or improvements did the operations advisor propose from the same review? Trace how the earlier results are reflected in the communicator's reply.

## B. Add conditions for the guest reply

**Mission: write a short reply that addresses both of the guest's concerns.**

Which role should receive this request? Here, ask the guest communicator. Append the following to **Guest Reply Writer → Editor → Messages → User**, leaving the review, references and System unchanged.

```text
For this reply, address both the check-in wait and the missing breakfast-hours information. Keep it under 90 words.
```

Run again and check the latest reply.

- Does it address both the check-in wait and missing breakfast-hours information?
- Does the reply reflect the feedback identified by the analyst?
- Can you identify how the operational proposals informed the reply? It need not repeat every internal proposal.
- Does the short reply still express thanks and acknowledge the guest's concerns?

If the first reply already met the conditions, changes may be small. Check **whether the roles and handoffs work as intended and the request is reflected**. Rerunning the system can also change earlier outputs.
