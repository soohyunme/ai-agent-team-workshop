## A. Change the travel preferences

Open **Start** and change only the **Value** fields below. You do not need to write a long request.

| Field | Meaning | Value to try |
| --- | --- | --- |
| interests | Sightseeing interests | `art, harbour views` |
| food | Food preference | `vegetarian dishes` |
| pace | Travel pace | `relaxed` — leave unchanged |

This example requests art, harbour views and vegetarian dishes. Keep field names unchanged and **leave the template's shared cards unchanged.**

The agents' User messages reference these short values to form the request for this run. Later, you can try your own preferences; if the supplied cards offer no match, the team should explain that limitation.

## B. Add an itinerary condition

Open **Trip Planner → Editor → Messages → System**. **Append** the following text to the existing instructions. Do not delete the existing message or change User.

```text
Keep only one sightseeing activity and include at least one rest break. Remove extra sightseeing activities from the draft if needed. Explain briefly what you changed, or say that the draft already met this rule.
```

This instruction asks the organizer to keep only one sightseeing activity, retain the rest break already required, and briefly explain what was removed.

In A, you change the **request for this run**. In B, you add a **rule for the agent to follow**. In the next step, you will check how both changes are reflected in the final itinerary.
