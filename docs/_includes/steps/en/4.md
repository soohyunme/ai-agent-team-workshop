## A. Create a new workflow

A **workflow** defines the order of tasks and the information passed between them. You will build one rather than import the completed example.

1. Select **+ beside Workflows** in Sim's left sidebar to create a workflow.
2. Right-click its name in the list and select **Rename**. Call it `My Hong Kong Team`.
3. Check for a **Start** block. If none is present, drag Start from the right-hand **Toolbar** onto the empty canvas. Keep only one Start.

Each box is a **block**. The basic exercise uses Start and three Agent blocks.

## B. Enter short travel preferences

Select Start and open **Editor**. Use **+** in the input fields section to add the three entries below, filling in **Name, Type and Value**. Description is optional.

| Name | Type | Value | Meaning |
| --- | --- | --- | --- |
| interests | string | `harbour views, photography, parks` | Sightseeing interests |
| food | string | `local dishes` | Food preference |
| pace | string | `relaxed` | Travel pace |

`string` means a text value. Use the exact field names shown: agents will use these names to read your request.

## C. Prepare the shared cards

Store the sightseeing and food cards in one place so all three specialists can read them. This is preparation, so copy the supplied data unchanged.

1. Open **··· → Variables** at the top of the right panel, above **Chat / Toolbar / Editor**. This is not the menu beside Workflows.
2. Select **+** in the Variables window.
3. Set **Name** to `cards` and **Type** to `Object`.
4. Copy everything below, including the braces, into **Value**. This editor supports multiline data.
5. Check for validation errors, then close Variables.

Object is a format for grouping information. You do not need to learn its syntax or edit the data for this exercise. This is shared travel data, not an API key.

## About the supplied cards

This run creates an itinerary draft using the **supplied sightseeing and food cards**. It does not search live information or make bookings. Food options are **fictional workshop examples**, not actual restaurants or menus.

The sightseeing and food cards are stored once as **shared data (cards)** in your workflow, and all three agents reference them. Start contains only the travel preferences to edit. You do not need to edit the shared data in this exercise; read the tables below.

### Sightseeing cards

| ID | Place | Area | Interests |
| --- | --- | --- | --- |
| S1 | Avenue of Stars | Tsim Sha Tsui | Harbour views, photography, Hong Kong cinema |
| S2 | Hong Kong Museum of Art | Tsim Sha Tsui | Art |
| S3 | Art Park | West Kowloon | Parks, harbour views, photography |

### Food cards — fictional examples, not real restaurants

| ID | Meal example | Area | Preference |
| --- | --- | --- | --- |
| F1 | Example dim sum meal | Tsim Sha Tsui | Local dishes |
| F2 | Example vegetable rice meal | Tsim Sha Tsui | Vegetarian dishes |
| F3 | Example noodle meal | West Kowloon | Local dishes |
| F4 | Example vegetable noodle meal | West Kowloon | Vegetarian dishes |

IDs and areas help you trace how the food specialist uses the sightseeing results. A rest break is also a planning placeholder, not a verified venue.

The short sightseeing descriptions and area labels draw on the Hong Kong Tourism Board's [Tsim Sha Tsui attractions guide](https://www.discoverhongkong.com/eng/attractions/top-things-to-see-and-do-around-tsim-sha-tsui-promenade.html) and [Art Park guide](https://www.discoverhongkong.com/eng/place-to-go/travel.guide-art-park.html). The food cards are teaching examples, not restaurant information from these sources.
